### ⚠️ 가장 중요한 교훈: eval_loss로 판단하지 말 것
세 런에서 eval_loss(flow-matching 목적함수)와 실제 액션 품질이 **서로 다른 방향으로** 갈렸다:
- joint_30hz: eval_loss 7.5k 이후 상승, 액션 지표는 **정체**(악화 아님)
- relarm: eval_loss 7.5k 이후 상승, 액션 지표는 **12.5k까지 계속 개선**
- 라운드1 3뷰/4뷰: 양쪽 다 eval_loss 반등, 액션 지표는 **15k까지 단조 개선**

**왜 갈리는가** (`gr00t_n1d7.py:228-278`):
```python
noise = randn(...); t = (1 - Beta(1.5,1.0)) * 0.999
loss = mse(model((1-t)*noise + t*actions, t, obs),  actions - noise)
```
1. **답이 원리적으로 없는 구간이 손실을 지배한다.** 타깃 `actions - noise`의 두 항을 모델은
   둘 다 못 본다(섞인 `x_t` 하나만 봄). t가 작으면 최적 예측조차 큰 잔차를 남기고, 이
   환원 불가능한 항이 손실 크기를 지배해 개선 가능한 부분을 덮는다.
2. **추론은 4스텝 Euler 적분이라 자기 교정적이다**(`:397`). 매 스텝 실제 도달한 `x_t`를
   다시 읽으므로 앞 스텝 오차가 회수된다. eval_loss는 각 t를 독립 채점해 이를 반영하지 않는다.
3. **eval_loss 상승 = 멀티모달 평균에서 특정 모드로 뾰족해진 것.** val 샘플이 다른 모드면
   회귀 오차는 커지지만, 그 모드가 옳으면 정답 궤적 하나와 비교하는 open-loop MSE는 좋아진다.
   (MSE가 같이 나빠지지 않았다는 사실 자체가 "옳은 쪽으로 뾰족해졌다"는 증거)
+ eval_loss는 매 평가마다 `noise`/`t`를 새로 뽑는 몬테카를로 추정치라 자체 분산도 있다.
  open-loop 스캔은 윈도우별 diffusion seed 고정이라 훨씬 조용하다.

→ 체크포인트 선택도, **조기 종료 판단도** `eval_val_mse.py` open-loop 스캔으로 할 것 (체크포인트당 ~3분).
→ VLA는 액션 재현 정확도가 목표라 목적함수가 평평해져도 더 긴 스케줄이 이득일 수 있다
   (OpenVLA도 같은 이유로 스텝을 크게 늘림). **스텝 상한을 넉넉히 두고 2,500스텝마다 스캔으로
   판단**하는 방식을 기본으로.
→ 단, "더 길게가 항상 이득"은 아니다. 라운드3에서 30k/256은 20k에 포화한 뒤 15k/192보다
   근소하게 나빴다(위 6번). **eval_loss가 아니라 open-loop 스캔이 판정자라는 원칙은 그대로이고,
   그 스캔이 "더 길게는 손해"라고 말할 수도 있다.**

## 데이터 품질 이슈와 조치 (2026-08-16)

### A. 텔레옵 정지 구간 — 제거함
팔 액션이 비트단위로 얼어붙은 구간이 학습 가중치를 왜곡. 30Hz 실측: 0.5초 이상 정지가

윈도우 기준 오염도 0.92% (466,575개 중 4,307개가 1.33초간 팔 0.5° 미만).
- 임계값 판정이 깨끗함: 0.5°→2°로 4배 올려도 해당 윈도우가 4,307→4,340개 (이봉분포)
- **RELATIVE에서 더 해로움**: 타깃이 정확히 0 → "출력 0" 지름길. ABSOLUTE는 현재 자세라 정보가 남음
- 조치: 정지 지점에서 **클립 분할**(이어붙이지 않음) → 새 불연속 없음을 실측 확인
  (프레임당 최대 팔 점프 33.01°로 원본과 동일, >5° 비율 1.844%→1.866%)
- exporter도 근본 수정: url_lerobot `--min-stall` (commit a4d5199)

### B. aug state 46차원 — 재설계
초기 50차원(root 7 + ee 12)에 세 가지 결함이 있어 아래로 교체:
| 제거/교체 | 실측 근거 |
|---|---|
| root x,y 제거 | 클립간/클립내 std 비율 **90.6× / 55.9×** → 사실상 클립 ID (leakage) |
| root z 제거 | 비율 1.1배지만 다리 관절의 결정론적 함수, 전체 변동 36mm |
| root_quat → **base_gravity** | quat은 yaw 지배(yaw std 109° vs roll 0.63°/pitch 1.07°), w·z 성분이 거의 순수 yaw. projected gravity는 yaw 불변 |
| ee_state → **FK 재계산** | 기록된 EE가 팔 관절보다 **10프레임(333ms) 지연**. URDF FK 대조: lag+10에서 3.0mm 일치, lag0에서 22.3mm 불일치 → 같은 행 안에서 모순. FK 적용 후 lag0 잔차 **0.0000mm** |
- FK 규약: G1 `g1_body29_hand14.urdf`, **waist=0 고정(몸통 좌표계)**, wrist_yaw 원점 + 로컬 x 0.05m, extrinsic xyz euler
- **base_gravity만이 진짜 새 정보** (관절각으로 복원 불가한 몸통 기울기). EE는 정보량 0의 재파라미터화
  → 라운드2 결과는 이 예측과 일치(팔 동률), 다만 그리퍼 개선의 출처는 미분리
